# Implementation Plan: AI-Native BD Lead Assistant

**Branch**: `004-ai-bd-assistant` | **Date**: 2026-07-13 | **Spec**: `specs/004-ai-bd-assistant/spec.md`
**Input**: Feature specification derived from CONCEPT.md, ARCHITECTURE.md, FEATURES.md, UI_UX.md and approved agentic build plan.

**Note**: This plan follows the Speckit workflow and the high-level plan in the session artifacts. See `.specify/templates/plan-template.md` for the execution workflow.

## Summary

Build the full AI-native BD assistant product:
- Backend (VPS/Docker) with auth (Google), per-user memory (Postgres + pgvector), LLM proxy (Gemini 2.5 Flash primary + Haiku 4.5), CrmClient abstraction, and orchestration.
- Web app for onboarding, demo, history, and account management.
- Thin MV3 browser extension as the daily driver.
- Keep MCP server working via shared core.
- v1 CRMs: Bitrix24 + HubSpot.

Primary approach: Refactor existing MCP code into reusable CrmClient + core logic, stand up backend + web mirroring vanguard-game patterns, add memory injection into AI prompts, deliver both clients against the same APIs.

## Technical Context

**Language/Version**: Python 3.12 (FastAPI backend + AI workers) + TypeScript (web + extension). Node 20+ for any thin API layer or build.
**Primary Dependencies**: FastAPI, SQLAlchemy + asyncpg + Alembic, Pydantic, google-genai + anthropic (LLM), python-jose + passlib (auth), React 18 + Vite + TypeScript + Zustand + Axios (web), Manifest V3 for extension.
**Storage**: PostgreSQL 16 + pgvector (users, leads, memory profiles, encrypted CRM tokens, history embeddings). Redis for queues/cache/rate limits.
**Testing**: pytest (backend), Playwright or Vitest (web), manual sandbox E2E for CRMs, unit tests for CrmClient adapters.
**Target Platform**: Linux VPS (Docker Compose deployment). Web: modern browsers. Extension: Chrome + Firefox.
**Project Type**: Full-stack web service + browser extension + thin MCP server wrapper.
**Performance Goals**: < 5s for AI enrichment (including preview); per-lead cost <$0.01.
**Constraints**: Cheap LLMs only in v1; envelope encryption for tokens; no remote code in extension (MV3); single VPS initially.
**Scale/Scope**: Early users (hundreds); MVP supports 2 CRMs, basic memory, web + extension clients.

- Memory: Postgres structured + pgvector for semantic recall of tone/history.
- Distribution: Web app first (onboarding + demo) + thin MV3 extension.
- v1 CRMs: Bitrix24 (existing integration) + HubSpot.

**Research tasks**:

- Token security: Envelope encryption + audit log required before any external user.
- MV3 constraints: All heavy work server-side; extension is thin.
